Challenges & Solutions

Problem: Payment Methods Not Appearing in Xendit

When sending an invoice creation payload, certain expected channels (e.g., specific e-wallets or virtual accounts) were not rendering on the Xendit payment link.

Technical Solution

Synchronized the `paymentMethods` payload configuration to strictly align with the activated channels on the Xendit merchant dashboard account, ensuring dynamic retrieval of available channels via API instead of hardcoding array lists.

Problem: Complexity of Voucher Stacking

Allowing multiple layers of vouchers (store-wide, product-specific, and membership levels) simultaneously led to massive edge cases, such as negative cart totals or invalid application sequences.

Technical Solution

Engineered a multi-layered, modular validation system implementing the Strategy Pattern. Rules (minimum purchase, quota limits, combinations rules) were parsed sequentially, applying math derivations safely at each middleware pipeline before final calculation.

Problem: Payment & Order State Synchronization

Race conditions where users close the website prematurely after paying, potentially leaving the database with a "Pending" order state although funds were successfully captured.

Technical Solution

Decoupled client actions from payment confirmations by heavily relying on webhook-based events. The custom ElysiaJS API listens strictly to Xendit's encrypted webhook payloads to accurately commit state mutations inside database transactions.
